# NEAR investment thesis — Priced for delivery

An investment thesis on NEAR, presented as two static pages: a full thesis dashboard and an invalidation terminal built around six falsifiers. The thesis dies by measurement, not by opinion — every falsifier carries a threshold and a reading, and the reader can try to trigger the two live ones.

**Verdict: priced for delivery.** At the snapshot price, the market is already paying for delivery that still has to happen. The thesis stands only while none of its falsifiers fire: one triggered falsifier downgrades it, two concurrent triggers end it.

## What is in this repo

| Path | What it is |
| --- | --- |
| `index.html` | The thesis dashboard — the full argument, scenario and valuation work, falsifier board. |
| `terminal.html` | The invalidation terminal — F1-F6 board, kill-switch sliders, live status chip. |
| `THESIS.md` | The thesis as plain text (same argument as the dashboard). |
| `data/` | Every series behind the figures: shipped CSVs/JSON, the falsifier readings (`falsifiers.json`), model outputs, and `manifest.json` (source + pull date for every file). |
| `figures/` | Figures 1-9 as PNG, regenerated by the figure scripts. |
| `model/` | The valuation model (`model.py` + `config.yaml`) behind V* and the scenario grid. |
| `scripts/` | `check_falsifiers.py` (the checker), `fetch.py` (data pulls), `fetch_f4_snapshot.py` (buyback-wallet snapshot), figure generators. |
| `queries/` | The BigQuery SQL (G1-G6) behind the `data/bq_*.csv` series. |
| `rebuild.sh` | One-command rebuild: fetch -> model -> figures -> falsifier check. |
| `REFERENCES.md` | Source list. |

There is no build step and no dependency to install. Both pages are self-contained static HTML files.

## Reproduce the numbers

Every load-bearing number in this report can be re-run from this repo. Three levels, by how much you want to redo:

**Level 1 — re-check the falsifiers (no credentials, ~10 seconds)**

```bash
python3 scripts/check_falsifiers.py
```

Re-evaluates F1-F6 from the shipped `data/` CSVs plus a keyless scrape of revenue.near.org, and rewrites `data/falsifiers.json`. This is the exact command that produced the shipped readings (0 of 6 triggered at the 14 Nov 2026 snapshot).

**Level 2 — rebuild model, figures and falsifiers from the shipped data (no credentials)**

```bash
pip install -r requirements.txt   # requests + matplotlib (Python 3.10+)
bash rebuild.sh --model-only
```

Re-runs `model/model.py`, regenerates `figures/fig1-fig9.png` (the figure scripts fetch live, keyless data), and finishes with the Level 1 check.

**Level 3 — full rebuild including fresh data pulls**

```bash
bash rebuild.sh
```

Runs `scripts/fetch.py` first (CoinGecko, DefiLlama and revenue.near.org are keyless). Two legs are credential-gated: the BigQuery series (`queries/*.sql` -> `data/bq_*.csv`) need a GCP project and credentials (see `.env.example`) — the shipped `bq_*.csv` files are quoted from the 11 Nov 2026 pull — and the NEAR Intents Explorer leg is JWT-gated. With `--allow-partial` the fetch skips gated sources instead of failing; the rebuild never presents stale data as fresh.

**Refreshing the F4 snapshot**

F4 reads a shipped on-chain snapshot, not a live call:

```bash
python3 scripts/fetch_f4_snapshot.py
```

Re-pulls the buyback wallet's trailing-30-day receipts from the NearBlocks API (no key) and rewrites `data/buyback_wallet_30d.json`; then re-run Level 1. The checker refuses to report F4 from a stale snapshot.

## Live data: how to re-check it

The numbers in the dashboard are frozen (see above). Live data can be re-checked, but a live result is shown as a note — it does **not** replace the frozen hero or model figures.

- In the dashboard, use the **Recheck live** button. The live result appears as a note alongside the frozen snapshot, so the two can be compared without overwriting the 14 Nov figures.
- In the terminal, F1 is auto-fetched live when the page opens. The status chip shows `LIVE · UPDATED HH:MM` on success.
- If a fetch fails, the pages keep the frozen snapshot values and say so — the snapshot is the fallback, never a silent substitute presented as live.

## The six falsifiers

Only **F1 and F2 can move**. They are driven by the live fetch and by the kill-switch sliders in the terminal, so a reader can drag volume, take rate, or capture down and watch the board react. **F3–F6 are static**, each for a different reason explained below.

| # | Falsifier | Live or static | Threshold | Reading, 14 Nov 2026 |
| --- | --- | --- | --- | --- |
| F1 | Intents volume demand | Live | Below $75M/day | $126.58M/day — not triggered |
| F2 | Take rate / capture | Live | Take below 3 bps, or capture below 15% | 5.13 bps / 31.5% — not triggered |
| F3 | HSP-029 live | Static | Not live by 30 Jun 2027 | Not yet decidable |
| F4 | Buyback wallet outflow | Static | Outflow above 5% in 30 days | 0 NEAR out — not triggered |
| F5 | ETF flows | Static | Outflow for 4 straight weeks | Cannot be checked |
| F6 | Revenue growth | Static | Run-rate fails to double | $22.28M/yr vs $1.41M/yr (15.8x) — not triggered |

**Pre-registration.** The six falsifiers above were defined before the 14 Nov 2026 snapshot, not after it. They were set out in the author's earlier public working repo, [near-investment-thesis](https://github.com/0xrard/near-investment-thesis) — its `data/falsifiers.json` was generated 13 Nov 2026 14:31 UTC (data as of 12 Nov 2026) with the same six falsifiers and the same thresholds, and its commit history (from 12 Nov 2026) predates this submission's snapshot. That repo remains public, so the pre-registration can be checked there.

Why F3–F6 do not update live:

- **F3** is a calendar test. Its deadline is 30 June 2027, so there is nothing to measure until that date approaches.
- **F4** is read from an on-chain snapshot of the buyback wallet. At the 14 Nov 2026 snapshot the wallet balance was 2,280,770.08 NEAR across 768 receipts, with zero outflow. Refreshing it means a new on-chain snapshot, not a page fetch.
- **F5** has no public endpoint for the ETF flow data it needs, so it is honestly reported as cannot be checked rather than estimated.
- **F6** is a monthly revenue run-rate. It changes when new monthly revenue data lands, not during the day, so a live fetch would add noise rather than information.

## Run it

Open `index.html` or `terminal.html` in any modern browser — that is all. To serve the folder locally instead:

```bash
python3 -m http.server 8000
# then open http://localhost:8000/ or http://localhost:8000/terminal.html
```

An internet connection is needed for the live re-check. Offline, both pages still work and simply show the 14 Nov 2026 frozen snapshot.

The site is also published with GitHub Pages from this repository: [github.com/0xrard/Near-Hackathon](https://github.com/0xrard/Near-Hackathon).
